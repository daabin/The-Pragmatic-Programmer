# 第二版序言

<a id="d24e196"></a>
早在 20 世纪 90 年代，我们就与项目出现问题的公司合作。我们发现自己对每个人都说了同样的话：也许你应该在发货之前进行测试；为什么代码只在玛丽的机器上构建？为什么没有人询问用户？

<a id="d24e198"></a>
为了节省与新客户打交道的时间，我们开始记下笔记。这些笔记就成了《程序员修炼之道》。令我们惊讶的是，这本书似乎引起了共鸣，并且在过去 20 年里一直很受欢迎。

<a id="d24e203"></a>
但对于软件来说，20 年是很多辈子的时间。如果把 1999 年的开发人员放到今天的团队中，他们会在这个陌生的新世界中挣扎。但 20 世纪 90 年代的世界对于今天的开发者来说同样陌生。书中对 CORBA、CASE 工具和索引循环等内容的引用最多是古怪的，更可能是令人困惑的。

<a id="d24e205"></a>
与此同时，20年对常识没有任何影响。技术可能已经改变，但人却没有。当时的做法和方法现在仍然是个好主意。这本书的这些方面已经很成熟了。

<a id="d24e207"></a>
因此，当需要制作这个 20 周年纪念版时，我们必须做出决定。我们可以检查并更新我们引用的技术，然后就到此为止了。或者，我们可以根据另外二十年的经验重新审视我们推荐的实践背后的假设。

<a id="d24e214"></a>
最后，我们两者都做到了。

<a id="d24e216"></a>
<a id="FNPTR-1"></a>
因此，这本书有点像忒修斯之船。[[1]](<Second Edition Acknowledgments.md#FOOTNOTE-1>) 书中大约三分之一的主题是全新的。其余的大部分都被部分或全部重写。我们的目的是让事情变得更清晰、更相关，并希望能够永恒。

<a id="d24e227"></a>
我们做出了一些艰难的决定。我们删除了资源附录，一方面是因为它不可能保持最新状态，另一方面是因为它更容易搜索您想要的内容。鉴于当前并行硬件的丰富性以及处理并行硬件的良好方法的缺乏，我们重新组织并重写了与并发相关的主题。我们添加了内容来反映不断变化的态度和环境，从我们帮助发起的敏捷运动，到对函数式编程习惯的日益接受，以及对隐私和安全的日益增长的需求。

<a id="d24e232"></a>
但有趣的是，我们之间关于这一版本内容的争论比我们编写第一版时要少得多。我们都觉得重要的东西更容易识别。

<a id="d24e234"></a>
无论如何，这本书就是结果。请尽情享受。也许采取一些新的做法。也许认为我们建议的某些内容是错误的。参与你的手艺。给我们反馈。

<a id="d24e237"></a>
但是，最重要的是，记住要让它变得有趣。
