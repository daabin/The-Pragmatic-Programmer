## 主题 16. 纯文本的力量

<a id="d24e6849"></a>
作为务实的程序员，我们的基础材料不是木头或铁，而是知识。我们将需求收集为知识，然后在我们的设计、实现、测试和文档中表达这些知识。我们相信持久存储知识的最佳格式是纯文本。通过纯文本，我们使自己能够使用我们可以使用的几乎所有工具以手动和编程方式操纵知识。

<a id="d24e6871"></a>
大多数二进制格式的问题是理解数据所需的上下文与数据本身是分开的。你人为地将数据与其含义分开。数据也可以被加密；如果没有应用程序逻辑来解析它，它绝对没有意义。然而，使用纯文本，您可以实现独立于创建它的应用程序的自描述数据流。

### 什么是纯文本？

<a id="d24e6885"></a>
纯文本由可打印的字符组成，以传达信息的形式。它可以像购物清单一样简单：

```
* milk
* lettuce
* coffee
```

<a id="d24e6897"></a>
或者像这本书的来源一样复杂（是的，它是纯文本的，这让出版商很懊恼，他们希望我们使用文字处理程序）。

<a id="d24e6899"></a>
信息部分很重要。以下是没有用的纯文本：

```
hlj;uijn bfjxrrctvh jkni'pio6p7gu;vh bjxrdi5rgvhj
```

<a id="d24e6905"></a>
这也不是：

```
Field19=467abe
```

<a id="d24e6912"></a>
读者不知道 467abe 的意义是什么。我们希望我们的纯文本能够被人类理解。

### 文字的力量

<a id="d24e6933"></a>
纯文本并不意味着文本是非结构化的； HTML、JSON、YAML等都是纯文本。网络上的大多数基本协议也是如此，例如 HTTP、SMTP、IMAP 等。这是有一些充分的理由的：

- 过时保险
- 利用现有工具
- 更容易测试

#### 过时保险

<a id="d24e6976"></a>
人类可读的数据形式和自描述数据将比所有其他形式的数据和创建它们的应用程序更长寿。时期。只要数据存在，您就有机会使用它——可能在编写数据的原始应用程序失效很久之后。

<a id="d24e6982"></a>
您可以在仅了解其格式的部分知识的情况下解析此类文件；对于大多数二进制文件，您必须了解整个格式的所有详细信息才能成功解析它。

<a id="d24e6988"></a>
<a id="FNPTR-24"></a>
考虑来自给定的某个遗留系统的数据文件。<a href="22%20Engineering%20Daybooks%20-%20daybook#FOOTNOTE-24">[24]</a> 您对原始应用程序知之甚少；对您来说重要的是它维护了客户的社会安全号码列表，您需要查找和提取该列表。在数据中，你会看到

```
123-45-6789
...
567-89-0123
...
901-23-4567
```

<a id="d24e7006"></a>
识别社会安全号码的格式后，您可以快速编写一个小程序来提取该数据 - 即使您没有文件中其他任何信息。

<a id="d24e7008"></a>
但想象一下，如果文件是这样格式化的：

```
AC27123456789B11P
...
XY43567890123QTYL
...
6T2190123456788AM
```

<a id="d24e7022"></a>
您可能没有那么容易认识到这些数字的重要性。这就是人类可读和人类可理解之间的区别。

<a id="d24e7033"></a>
当我们这样做时，FIELD10 也没有多大帮助。像这样的东西

```
123-45-6789
```

<a id="d24e7042"></a>
使该练习变得轻而易举，并确保数据的寿命比创建它的任何项目都长。

#### 杠杆作用

<a id="d24e7047"></a>
事实上，计算领域中的每个工具，从版本控制系统到编辑器再到命令行工具，都可以对纯文本进行操作。

<a id="d24e7056"></a>
<a id="d24e7068"></a>
<a id="d24e7070"></a>
Unix 哲学

Unix 因围绕小而锋利的工具的哲学而设计，每个工具都旨在做好一件事。这一理念是通过使用通用的底层格式（面向行的纯文本文件）来实现的。用于系统管理（用户和密码、网络配置等）的数据库均以纯文本文件形式保存。 （一些系统还维护某些数据库的二进制形式作为性能优化。纯文本版本保留作为二进制版本的接口。）

当系统崩溃时，您可能只面临一个最小的环境来恢复它（例如，您可能无法访问图形驱动程序）。像这样的情况确实可以让你体会到纯文本的简单性。

纯文本也更容易搜索。如果您不记得哪个配置文件管理您的系统备份，快速 grep -r backup /etc 应该会告诉您。

<a id="d24e7075"></a>
例如，假设您有一个大型应用程序的生产部署，其中包含复杂的特定于站点的配置文件。如果此文件是纯文本，您可以将其置于版本控制系统下（请参阅主题 19，<a href="19%20Version%20Control%20-%20version_control#version_control">版本控制</a>），以便自动保留所有更改的历史记录。文件比较工具（例如 diff 和 fc）让您可以一目了然地看到所做的更改，而 sum 则可以让您生成校验和来监视文件是否有意外（或恶意）修改。

#### 更容易测试

<a id="d24e7100"></a>
如果您使用纯文本创建合成数据来驱动系统测试，那么添加、更新或修改测试数据就很简单，而无需创建任何特殊工具来执行此操作。同样，回归测试的纯文本输出可以使用 shell 命令或简单的脚本进行简单的分析。

### 最小公分母

<a id="d24e7112"></a>
即使未来基于区块链的智能代理可以自主地在狂野而危险的互联网上行走，在它们之间协商数据交换，无处不在的文本文件仍然存在。事实上，在异构环境中，纯文本的优点可以超过所有缺点。您需要确保所有各方都可以使用通用标准进行通信。纯文本就是这个标准。
