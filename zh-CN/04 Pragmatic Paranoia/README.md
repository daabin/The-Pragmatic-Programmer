# 第 4 章 - 务实的偏执

**提示 36：你无法编写完美的软件**

<a id="d24e8958"></a>
疼吗？不应该。接受它作为生活的公理。拥抱它。庆祝一下。因为完美的软件并不存在。在计算机的短暂历史中，没有人编写过完美的软件。你不太可能成为第一个。除非你接受这一事实，否则你最终会浪费时间和精力去追逐一个不可能的梦想。

<a id="d24e8964"></a>
那么，鉴于这一令人沮丧的现实，务实的程序员如何将其转化为优势呢？这就是本章的主题。

<a id="d24e8966"></a>
每个人都知道他们个人是地球上唯一的好司机。世界其他地方都在等着他们，冲过停车标志，在车道之间穿梭，不指示转弯，打电话发短信，而且通常没有达到我们的标准。所以我们采取防御性驾驶。我们防患于未然，预见意外情况，永远不会让自己陷入无法自拔的境地。

<a id="d24e8968"></a>
与编码的类比是非常明显的。我们不断地与其他人的代码（可能不符合我们的高标准的代码）进行交互，并处理可能有效或无效的输入。所以我们被教导要防御性地编码。如果有任何疑问，我们会验证所提供的所有信息。我们使用断言来检测不良数据，并且不信任来自潜在攻击者或巨魔的数据。我们检查一致性，对数据库列施加约束，并且通常自我感觉良好。

<a id="d24e8970"></a>
但务实的程序员更进一步。他们也不相信自己。务实的程序员知道没有人能写出完美的代码，包括他们自己，因此他们会针对自己的错误建立防御措施。我们在主题 23 [*按合同设计*](<23 Design by Contract - dbc.md#dbc>) 中描述了第一个防御措施：客户和供应商必须就权利和责任达成一致。

<a id="d24e8986"></a>
在主题 24 [*死程序不会说谎*](<24 Dead Programs Tell No Lies - crash_early.md#crash_early>) 中，我们希望确保在解决错误时不会造成任何损害。因此，我们尝试经常检查并在出现问题时终止程序。

<a id="d24e9002"></a>
主题 25，[*断言编程*](<25 Assertive Programming - assertions.md#assertions>) 描述了一种简单的一路检查方法 - 编写主动验证您的假设的代码。

<a id="d24e9026"></a>
随着您的程序变得更加动态，您会发现自己需要处理系统资源（内存、文件、设备等）。在主题 26 [*如何平衡资源*](<26 How to Balance Resources - balance_resources.md#balance_resources>) 中，我们将建议确保您不会失败的方法。

<a id="d24e9042"></a>
最重要的是，我们始终坚持小步前进，如主题 27，[*不要跑过你的车头灯*](<27 Don't Outrun Your Headlights - headlights.md#headlights>) 中所述，这样我们就不会从悬崖边缘掉下来。

<a id="d24e9063"></a>
在一个充满不完美系统、荒谬的时间尺度、可笑的工具和不可能的要求的世界里，让我们谨慎行事。正如伍迪·艾伦所说：“当每个人都想攻击你时，偏执就是一种好的想法。”
