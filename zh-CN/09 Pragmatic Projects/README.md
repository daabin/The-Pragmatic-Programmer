# 第 9 章 - 务实的项目

<a id="d24e25705"></a>
当您的项目开始进行时，我们需要摆脱个人理念和编码问题，转而讨论更大的、项目规模的问题。我们不会详细讨论项目管理的细节，但我们将讨论一些可以成就或破坏任何项目的关键领域。

<a id="d24e25707"></a>
一旦有多个人参与一个项目，您就需要建立一些基本规则并相应地委派项目的各个部分。在主题 49 [*务实的团队*](<49 Pragmatic Teams - teams.md#teams>) 中，我们将展示如何在尊重务实哲学的同时做到这一点。

<a id="d24e25715"></a>
软件开发方法的目的是帮助人们协同工作。您和您的团队是否在做适合您的事情，或者您是否只投资于琐碎的表面工件，而没有获得应有的真正好处？我们将了解主题 50 [*椰子不适合*](<50 Coconuts Don't Cut It - do_what_works.md#do_what_works>) 的原因，并提供成功的真正秘诀。

<a id="d24e25731"></a>
当然，如果您不能一致且可靠地交付软件，那么这一切都不重要。这是版本控制、测试和自动化神奇三重奏的基础：主题 51，[*实用的入门套件*](<51 Pragmatic Starter Kit - starter_kit.md#starter_kit>)。

<a id="d24e25768"></a>
但最终，成功与否取决于情人——项目的赞助商。对成功的看法才是最重要的，在主题 52 [*取悦您的用户*](<52 Delight Your Users - delight.md#delight>) 中，我们将向您展示如何取悦每个项目的赞助商。

<a id="d24e25789"></a>
本书中的最后一个技巧是其他所有技巧的直接结果。在主题 53 [*傲慢与偏见*](<53 Pride and Prejudice - jane_austen.md#jane_austen>) 中，我们要求您在您的作品上签名，并为您所做的事情感到自豪。
