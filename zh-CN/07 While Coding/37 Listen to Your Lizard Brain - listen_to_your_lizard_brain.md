## 主题 37. 倾听你的蜥蜴脑

> 只有人类才能直接观察某物，拥有做出准确预测所需的所有信息，甚至可能暂时做出准确的预测，然后说事实并非如此。
>
> 加文·德·贝克尔,
> 恐惧的礼物

<a id="d24e19357"></a>
加文·德贝克尔一生的工作就是帮助人们保护自己。他的书 [*恐惧的礼物：以及其他保护我们免受暴力的生存信号* [de 98]](<../A2 Exercise Answers/README.md#d6040e275>) 概括了他的信息。贯穿这本书的关键主题之一是，作为复杂的人类，我们已经学会了忽视自己动物性的一面；我们的本能，我们的蜥蜴大脑。他声称，大多数在街上遭到袭击的人在袭击前都意识到自己感到不舒服或紧张。这些人只是告诉自己他们很愚蠢。然后那个人影从黑暗的门口出现了……

<a id="d24e19380"></a>
本能只是对我们无意识大脑中的模式的反应。有些是天生的，有些是通过重复习得的。当你获得作为程序员的经验时，你的大脑正在沉积一层层的隐性知识：有效的事情，无效的事情，某种错误的可能原因，以及你在日常生活中注意到的所有事情。当你停止与某人聊天时，即使你没有意识到自己正在这样做，这也是你大脑中按下保存文件键的部分。

<a id="d24e19397"></a>
无论其来源如何，本能都有一个共同点：它们没有言语。本能让你感觉，而不是思考。因此，当本能被触发时，您不会看到一个闪烁的灯泡，周围还缠着横幅。相反，你会感到紧张、恶心，或者觉得这工作量太大了。

<a id="d24e19399"></a>
诀窍是首先注意到它正在发生，然后找出原因。首先让我们看一下几种常见的情况，在这些情况下，你内心的蜥蜴试图告诉你一些事情。然后我们将讨论如何让本能的大脑摆脱它的保护层。

### 对空白页的恐惧

<a id="d24e19404"></a>
每个人都害怕空荡荡的屏幕，害怕被一堆空无一物包围的孤独闪烁的光标。开始一个新项目（甚至是现有项目中的新模块）可能是一种令人不安的经历。我们中的许多人宁愿推迟做出开始的最初承诺。

<a id="d24e19415"></a>
我们认为有两个问题导致了这种情况，并且都有相同的解决方案。

<a id="d24e19417"></a>
一个问题是你的蜥蜴大脑试图告诉你一些事情；在感知的表面之下潜藏着某种怀疑。这很重要。

<a id="d24e19419"></a>
作为一名开发人员，您一直在尝试一些事情，看看哪些有效，哪些无效。你一直在积累经验和智慧。当你感到一种挥之不去的疑虑，或者在面对一项任务时感到有些不情愿时，这可能是一种试图对你说话的经历。注意它。你可能无法准确指出问题出在哪里，但给它一些时间，你的疑虑可能会具体化为更可靠的东西，一些你可以解决的东西。让你的直觉为你的表现做出贡献。

<a id="d24e19421"></a>
另一个问题有点平淡：您可能只是担心自己会犯错误。

<a id="d24e19432"></a>
这是一种合理的恐惧。我们开发人员在代码中投入了很多精力；我们可以将代码中的错误视为对我们能力的反映。也许还有冒名顶替综合症的因素。我们可能认为这个项目超出了我们的能力范围。我们看不到最后的路；我们会走到这一步，然后被迫承认我们迷路了。

### 与自己战斗

<a id="d24e19442"></a>
有时，代码会从你的大脑飞到编辑器中：想法似乎不费吹灰之力就变成了碎片。

<a id="d24e19444"></a>
其他时候，编码感觉就像在泥泞中爬山。每走一步都需要付出巨大的努力，每走三步就会向后退两步。

<a id="d24e19446"></a>
但是，作为一名专业人士，你要继续前进，在泥泞的道路上迈出一步：你有工作要做。不幸的是，这可能与您应该做的完全相反。

<a id="d24e19448"></a>
你的代码试图告诉你一些事情。据说这比应有的更难。也许结构或设计是错误的，也许你正在解决错误的问题，或者也许你只是创造了一个蚂蚁农场的错误。不管是什么原因，你的蜥蜴大脑正在感知来自代码的反馈，并且拼命地试图让你倾听。

### 如何说话蜥蜴

<a id="d24e19457"></a>
我们经常谈论倾听你的直觉，倾听你无意识的蜥蜴大脑。技术总是相同的。

**提示 61：倾听你内心的蜥蜴**

<a id="d24e19465"></a>
首先，停止你正在做的事情。给自己一点时间和空间，让你的大脑自行组织起来。停止思考代码，暂时远离键盘做一些相当无意识的事情。散步，吃午饭，和某人聊天。也许就这样睡吧。让这些想法自行渗透到你的大脑各层：你不能强迫它。最终它们可能会上升到意识层面，你就拥有了其中一个，哈哈！时刻。

<a id="d24e19474"></a>
如果这不起作用，请尝试将问题外部化。对您正在编写的代码进行涂鸦，或者向同事（最好不是程序员）或您的橡皮鸭解释它。让你大脑的不同部分接触到这个问题，看看它们是否能更好地处理困扰你的事情。我们已经记不清有多少次谈话中，其中一个人向另一个人解释问题，然后突然说：“哦！当然！”并停下来修理它。

<a id="d24e19488"></a>
但也许你已经尝试过这些方法，但仍然陷入困境。是时候采取行动了。我们需要告诉你的大脑，你要做的事情并不重要。我们通过原型设计来做到这一点。

### 玩耍时间到了！

<a id="d24e19493"></a>
安迪和戴夫都花了几个小时查看空的编辑器缓冲区。我们将输入一些代码，然后看看天花板，然后再喝一杯，然后输入更多代码，然后去读一个关于有两条尾巴的猫的有趣故事，然后输入更多代码，然后全选/删除并重新开始。又来了。又来了。

<a id="d24e19499"></a>
多年来，我们发现了一种似乎有效的大脑黑客方法。告诉自己你需要制作一些东西的原型。如果您面临空白屏幕，请查找您想要探索的项目的某些方面。也许您正在使用一个新框架，并且想了解它如何进行数据绑定。或者它可能是一种新算法，您想探索它在边缘情况下的工作原理。或者您可能想尝试几种不同风格的用户交互。

<a id="d24e19501"></a>
如果您正在处理现有代码并且它正在推迟，那么请将其存放在某个地方并制作类似的原型。

<a id="d24e19503"></a>
执行以下操作。

<a id="d24e19507"></a>
<a id="d24e19510"></a>
<a id="d24e19517"></a>
<a id="d24e19520"></a>
1. 在便利贴上写下“我正在制作原型”，然后将其贴在屏幕一侧。
2. 提醒自己原型注定会失败。并提醒自己，即使原型没有失败，也会被丢弃。这样做没有什么坏处。
3. 在空的编辑器缓冲区中，创建一条注释，用一句话描述您想要学习或做什么。
4. 开始编码。

<a id="d24e19522"></a>
如果您开始有疑问，请查看便签。

<a id="d24e19524"></a>
如果在编码过程中，那个挥之不去的疑虑突然变成了一个坚实的担忧，那么就解决它。

<a id="d24e19526"></a>
如果实验结束后你仍然感到不安，请重新开始散步、谈话和休息。

<a id="d24e19528"></a>
但是，根据我们的经验，在第一个原型的某个时刻，您会惊讶地发现自己随着音乐哼唱，享受着创建代码的感觉。紧张感将会消失，取而代之的是一种紧迫感：让我们完成这件事！

<a id="d24e19530"></a>
在这个阶段，你知道该怎么做。删除所有原型代码，扔掉便利贴，并用明亮、闪亮的新代码填充空的编辑器缓冲区。

### 不仅仅是您的代码

<a id="d24e19538"></a>
我们工作的很大一部分是处理现有代码，这些代码通常是由其他人编写的。这些人对你会有不同的直觉，因此他们做出的决定也会不同。不一定更糟；只是不同。

<a id="d24e19549"></a>
你可以机械地阅读他们的代码，费力地阅读它们，并在看似重要的内容上做笔记。这是一件苦差事，但很有效。

<a id="d24e19551"></a>
或者你可以尝试做一个实验。当你发现事情的处理方式看起来很奇怪时，把它记下来。继续这样做，并寻找模式。如果您能看到是什么驱使他们以这种方式编写代码，您可能会发现理解它的工作变得容易得多。你将能够有意识地应用他们默认应用的模式。

<a id="d24e19557"></a>
在此过程中您可能会学到一些新东西。

### 不仅仅是代码

<a id="d24e19563"></a>
在编码时学会倾听自己的直觉是一项需要培养的重要技能。但它适用于更大的图景。有时感觉设计是错误的，或者某些要求让你感到不安。停下来分析这些感受。如果您处于支持性环境中，请大声表达出来。探索它们。很可能那个黑暗的门口潜伏着什么东西。听从你的直觉，在问题出现之前避免它。
