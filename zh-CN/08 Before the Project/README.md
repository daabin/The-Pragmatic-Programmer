# 第 8 章 - 项目启动前

<a id="d24e24301"></a>
在项目一开始，您和团队需要了解需求。仅仅被告知要做什么或倾听用户的意见是不够的：阅读主题 45，[*需求坑*](<45 The Requirements Pit - requirements.md#requirements>) 并了解如何避免常见的陷阱和陷阱。

<a id="d24e24309"></a>
传统智慧和约束管理是主题 46，[*解决不可能的难题*](<46 Solving Impossible Puzzles - outta_box.md#outta_box>) 的主题。无论您是在执行需求、分析、编码还是测试，困难的问题都会出现。大多数时候，它们不会像最初看起来那么困难。

<a id="d24e24322"></a>
当那个不可能的项目出现时，我们喜欢转向我们的秘密武器：主题 47，[*共同努力*](<47 Working Together - working_together.md#working_together>)。我们所说的“一起工作”并不是指共享大量的需求文档、发送大量抄送的电子邮件或忍受无休止的会议。我们的意思是在编码时一起解决问题。我们将向您展示您需要谁以及如何开始。

<a id="d24e24335"></a>
尽管敏捷宣言以“个体以及流程和工具上的交互”开头，但实际上所有“敏捷”项目都是从对他们将使用哪个流程和工具的讽刺性讨论开始的。但无论它经过多么深思熟虑，无论它包含哪些“最佳实践”，没有任何方法可以取代思考。您不需要任何特定的流程或工具，您需要的是主题 48，[*敏捷的本质*](<48 The Essence of Agility - essence_of_agility.md#essence_of_agility>)。

<a id="d24e24352"></a>
在项目开始之前解决这些关键问题，您可以更好地避免“分析瘫痪”并真正开始并完成您的成功项目。
