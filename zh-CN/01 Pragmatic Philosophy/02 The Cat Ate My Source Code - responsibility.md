## 主题 2. 猫吃掉了我的源码

> 所有弱点中最大的弱点是害怕显得软弱。
>
> J.B. Bossuet，《圣经中的政治》，1709 年

<a id="d24e900"></a>
务实哲学的基石之一是对自己和自己在职业发展、学习和教育、项目以及日常工作方面的行为负责。务实的程序员负责自己的职业生涯，并且不怕承认无知或错误。当然，这不是编程中最令人愉快的方面，但它会发生——即使是在最好的项目上。尽管进行了彻底的测试、良好的文档和可靠的自动化，但事情还是出了问题。交货晚了。出现不可预见的技术问题。

<a id="d24e921"></a>
这些事情发生了，我们会尽力以专业的方式处理它们。这意味着诚实和直接。我们可以为自己的能力感到自豪，但我们必须承认自己的缺点——我们的无知和错误。

### 团队信任

<a id="d24e926"></a>
<a id="FNPTR-4"></a>
最重要的是，您的团队需要能够信任和依赖您，而且您也需要能够轻松地依赖他们每个人。根据研究文献，团队中的信任对于创造力和协作绝对至关重要。[[4]](<07 Communicate - communicate.md#FOOTNOTE-4>) 在基于信任的健康环境中，您可以安全地表达自己的想法，提出您的想法，并依赖您的团队成员，而团队成员反过来也可以依赖您。没有信任，好吧……

<a id="d24e963"></a>
想象一下，一支高科技隐形忍者队伍潜入恶棍的邪恶巢穴。经过几个月的计划和精心的执行，您已经在现场实现了。现在轮到你设置激光制导网格了：“抱歉，各位，我没有激光。那只猫正在玩红点，我把它落在家里了。”

<a id="d24e965"></a>
这种对信任的破坏可能很难修复。

### 承担责任

<a id="d24e970"></a>
责任是你主动同意的事情。您承诺确保某件事正确完成，但您不一定能直接控制它的每个方面。除了尽自己最大的努力之外，您还必须分析情况以排除您无法控制的风险。您有权不对不可能的情况承担责任，或者在风险太大或道德影响太粗略的情况下不承担责任。您必须根据自己的价值观和判断做出决定。

<a id="d24e979"></a>
当您确实接受结果的责任时，您应该预期要为此承担责任。当你犯了错误（就像我们所有人一样）或判断错误时，诚实地承认并尝试提供选择。

<a id="d24e984"></a>
不要责怪某人或某事，也不要编造借口。不要将所有问题归咎于供应商、编程语言、管理层或您的同事。所有这些都可能发挥作用，但由您来提供解决方案，而不是借口。

<a id="d24e996"></a>
如果存在供应商无法为您解决的风险，那么您应该制定应急计划。如果您的海量存储崩溃了（带走了所有源代码）并且您没有备份，那是您的错。告诉你的老板“猫吃了我的源代码”并不能解决问题。

**提示 4：提供选择，不要找蹩脚的借口**

<a id="d24e1009"></a>
在你接近任何人告诉他们为什么某件事无法完成、迟到或被破坏之前，请停下来听听自己的声音。与显示器上的橡皮鸭或猫交谈。你的借口听起来合理还是愚蠢？你的老板听起来怎么样？

<a id="d24e1011"></a>
在脑海中回想一下对话。对方可能会说什么？他们会问，“你试过这个吗……”或者“你没有考虑过吗？”你会如何回应？在你去告诉他们坏消息之前，你还能尝试什么吗？有时，你只是知道他们会说什么，所以省去他们的麻烦。

<a id="d24e1016"></a>
与其找借口，不如提供选择。不要说做不到；解释可以采取哪些措施来挽救局势。代码必须删除吗？告诉他们这一点，并解释重构的价值（参见主题 40，[*重构*](<../07 While Coding/40 Refactoring - refactor.md#refactor>)）。

<a id="d24e1023"></a>
您是否需要花时间进行原型设计以确定最佳的继续方法（请参阅主题 13，[*原型和便利贴*](<../02 Pragmatic Approach/13 Prototypes and Post-it Notes - prototyping.md#prototyping>)）？您是否需要引入更好的测试（请参阅主题 41、[*测试代码*](<../07 While Coding/41 Test to Code - test_to_build.md#test_to_build>) 和 [*无情且持续的测试*](<../09 Pragmatic Projects/51 Pragmatic Starter Kit - starter_kit.md#testing>)）或自动化以防止再次发生？

<a id="d24e1031"></a>
也许您需要额外的资源来完成此任务。或者也许您需要花更多时间与用户相处？或者也许只是你：你需要更深入地学习一些技巧或技术吗？一本书或一门课程会有帮助吗？不要害怕询问或承认您需要帮助。

<a id="d24e1034"></a>
在大声说出那些蹩脚的借口之前，先试着把它们扫掉。如果必须的话，请先告诉你的猫。毕竟，如果小提德尔要承担责任的话……

### 挑战

<a id="d24e1048"></a>
<a id="d24e1055"></a>
- 当有人（例如银行出纳员、汽车修理工或职员）以蹩脚的借口来找你时，你会如何反应？您对他们和他们的公司有何看法？
- 当你发现自己说“我不知道”时，一定要接着说“——但我会找到答案的”。这是承认自己不知道的事情，然后像专业人士一样承担责任的好方法。
