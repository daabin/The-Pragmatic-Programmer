## 主题 6. 你的知识资产组合

> 对知识的投资总是能带来最大的利益。
>
> 本杰明·富兰克林

<a id="d24e1571"></a>
啊，善良的老本·富兰克林——从不迷失精辟的说教。为什么，如果我们能早睡早起，我们就会成为伟大的程序员，对吧？早起的鸟儿有虫吃，但早起的虫子会怎样呢？

<a id="d24e1592"></a>
不过，在这件事上，本确实一针见血。您的知识和经验是您最重要的日常专业资产。

<a id="d24e1594"></a>
<a id="FNPTR-9"></a>
不幸的是，它们即将过期。[[9]](<07 Communicate - communicate.md#FOOTNOTE-9>) 随着新技术、语言和环境的开发，您的知识会变得过时。不断变化的市场力量可能会使您的经验过时或无关紧要。鉴于我们技术社会的变化速度不断加快，这种情况可能会很快发生。

<a id="d24e1618"></a>
随着您知识的价值下降，您对公司或客户的价值也会下降。我们希望防止这种情况发生。

<a id="d24e1620"></a>
你学习新事物的能力是你最重要的战略资产。但是你如何学会如何学习，以及你如何知道要学什么？

### 您的知识组合

<a id="d24e1631"></a>
我们喜欢将程序员了解的有关计算的所有事实、他们工作的应用程序领域以及他们的所有经验视为他们的知识组合。管理知识组合与管理金融组合非常相似：

1. 认真的投资者定期投资——作为一种习惯。
2. 多元化是长期成功的关键。
3. 聪明的投资者会在保守投资和高风险、高回报投资之间平衡其投资组合。
4. 投资者试图低买高卖以获得最大回报。
5. 应定期审查和重新平衡投资组合。

<a id="d24e1656"></a>
为了在你的职业生涯中取得成功，你必须使用这些相同的指导方针来投资你的知识组合。

<a id="d24e1658"></a>
好消息是，管理此类投资是一项技能，就像任何其他技能一样——可以学习。诀窍是让自己一开始就这样做并养成习惯。制定一个你遵循的惯例，直到你的大脑将其内化。那时，你会发现自己在自动吸收新知识。

### 建立你的投资组合

<a id="d24e1667"></a>
<a id="d24e1675"></a>
<a id="d24e1688"></a>
<a id="d24e1697"></a>
<a id="d24e1702"></a>
定期投资：就像金融投资一样，您必须定期投资您的知识组合，即使只是少量。习惯与总数一样重要，因此计划使用一致的时间和地点，远离打扰。下一节列出了一些示例目标。

多元化：你知道的不同事物越多，你就越有价值。作为基线，您需要了解当前正在使用的特定技术的细节。但不要就此止步。计算的面貌瞬息万变——今天的热门技术明天可能几乎毫无用处（或者至少没有需求）。您熟悉的技术越多，您就越能够适应变化。并且不要忘记您需要的所有其他技能，包括非技术领域的技能。

管理风险：技术的存在范围从有风险、潜在高回报到低风险、低回报标准。将所有资金投入可能突然崩盘的高风险股票并不是一个好主意，也不应该保守地投入所有资金而错过可能的机会。不要把所有的技术鸡蛋放在同一个篮子里。

低买高卖：在新兴技术流行之前学习它就像找到一只被低估的股票一样困难，但回报也同样丰厚。在 Java 刚被引入、未知的时候学习 Java 在当时可能是有风险的，但当它后来成为行业中流砥柱时，它为早期采用者带来了丰厚的回报。

审查和重新平衡：这是一个非常有活力的行业。您上个月开始研究的热门技术现在可能已经很冷了。也许您需要温习一下您已经有一段时间没有使用的数据库技术。或者，如果您尝试其他语言，也许您可​​以更好地适应新的职位空缺……。

在所有这些准则中，最重要也是最简单的准则：

**提示 9：定期投资您的知识组合**

### 目标

<a id="d24e1718"></a>
既然您已经了解了向您的知识组合添加什么内容以及何时添加的一些指导原则，那么获取知识资本来为您的知识组合提供资金的最佳方式是什么？以下是一些建议：

<a id="d24e1733"></a>
<a id="d24e1752"></a>
<a id="FNPTR-10"></a>
<a id="d24e1771"></a>
<a id="d24e1784"></a>
<a id="d24e1791"></a>
<a id="d24e1815"></a>
<a id="d24e1827"></a>
每年至少学习一门新语言：不同的语言以不同的方式解决相同的问题。通过学习几种不同的方法，您可以帮助拓宽您的思维并避免陷入困境。此外，由于有大量免费软件，学习多种语言变得很容易。

每个月阅读一本技术书籍：虽然网络上有大量的简短论文和偶尔可靠的答案，但为了深入理解，您需要长篇书籍。浏览书商，查找与您当前项目相关的有趣主题的技术书籍。[[10]](<07 Communicate - communicate.md#FOOTNOTE-10>) 一旦养成习惯，每月读一本书。掌握当前正在使用的技术后，请扩展并研究一些与您的项目无关的技术。

也要阅读非技术书籍：重要的是要记住，计算机是由人使用的——你试图满足他们的需求。你与人一起工作，受人雇佣，也被人黑客攻击。不要忘记等式中人性的一面，因为这需要完全不同的技能（讽刺的是，我们称之为软技能，但它们实际上很难掌握）。

上课：在当地或在线学院或大学，或者在附近的下一个贸易展览或会议上寻找有趣的课程。

参加本地用户小组和聚会：孤立可能对你的职业生涯造成致命的影响；了解人们在公司之外正在做什么。不要只是去听：积极参与。

尝试不同的环境：如果您只在 Windows 中工作，请花一些时间使用 Linux。如果您只使用过 makefile 和编辑器，请尝试具有尖端功能的复杂 IDE，反之亦然。

保持最新：在线阅读与您当前项目不同的技术的新闻和帖子。这是了解其他人的体验、他们使用的特定术语等等的好方法。

<a id="d24e1838"></a>
继续投资很重要。一旦您对某种新语言或新技术感到满意，就可以继续前进。学习另一个。

<a id="d24e1840"></a>
无论您是否在项目中使用过这些技术，甚至是否将它们写在简历中，都无关紧要。学习的过程将拓展你的思维，让你接触新的可能性和新的做事方式。思想的交叉传播很重要；尝试将您学到的经验教训应用到当前的项目中。即使您的项目不使用该技术，也许您可​​以借用一些想法。例如，熟悉面向对象，您就会以不同的方式编写过程程序。了解函数式编程范例，您就会以不同的方式编写面向对象的代码，等等。

### 学习机会

<a id="d24e1847"></a>
因此，您正在如饥似渴地阅读，掌握了您所在领域的所有最新突破性发展（这不是一件容易的事），有人问您一个问题。你根本不知道答案是什么，却坦率地承认了这一点。

<a id="d24e1858"></a>
不要让它停在那里。将其视为寻找答案的个人挑战。四处询问。搜索网络——还有学术部分，而不仅仅是消费者部分。

<a id="d24e1862"></a>
如果你自己找不到答案，那就看看谁能找到答案。不要让它休息。与其他人交谈将有助于建立你的个人网络，并且你可能会惊讶地发现其他不相关问题的解决方案。而那个旧的投资组合一直在变得越来越大......

<a id="d24e1867"></a>
所有这些阅读和研究都需要时间，而时间已经供不应求。所以你需要提前计划。在闲暇的时刻总要读点东西。等待医生和牙医的时间可能是一个很好的机会来补充阅读内容，但一定要带上自己的电子阅读器，否则您可能会发现自己正在翻阅一篇 1973 年有关巴布亚新几内亚的卷角文章。

### 批判性思维

<a id="d24e1879"></a>
最后重要的一点是批判性地思考你所读到和听到的内容。您需要确保您的投资组合中的知识是准确的，并且不受供应商或媒体炒作的影响。谨防那些坚持认为他们的教条提供了唯一答案的狂热者——它可能适用也可能不适用于您和您的项目。

<a id="d24e1901"></a>
永远不要低估商业主义的力量。仅仅因为网络搜索引擎首先列出命中并不意味着它是最佳匹配；而是意味着它是最佳匹配。内容提供商可以付费以获得最高计费。仅仅因为书店突出展示一本书并不意味着它是一本好书，甚至不意味着它很受欢迎；他们可能是付钱把它放在那里的。

**提示 10：批判性地分析你所读到和听到的内容**

<a id="d24e1909"></a>
批判性思维本身就是一门完整的学科，我们鼓励您尽可能阅读和研究有关它的内容。与此同时，这里有一些需要提出和思考的问题。

<a id="d24e1924"></a>
<a id="d24e1931"></a>
<a id="d24e1941"></a>
<a id="d24e1950"></a>
<a id="d24e1960"></a>
问“五个为什么”：最喜欢的咨询技巧：问“为什么？”至少五次。提出问题，然后得到答案。通过询问“为什么？”来深入挖掘。重复一遍，就好像你是一个脾气暴躁的四岁孩子（但有礼貌）。通过这种方式，您也许能够更接近根本原因。

这对谁有利？ ：这可能听起来有些愤世嫉俗，但跟随金钱可能是一个非常有帮助的分析途径。给其他人或另一个组织带来的好处可能与您自己的利益一致，也可能不一致。

背景是什么？ ：一切都发生在其自身的环境中，这就是为什么“一刀切”的解决方案通常不会。考虑一篇宣扬“最佳实践”的文章或书籍。需要考虑的好问题是“最适合谁？”先决条件是什么，短期和长期的后果是什么？

这会在何时何地发挥作用？ : 什么情况下？是不是太晚了？太早了？不要停留在一阶思维（接下来会发生什么），而是使用二阶思维：之后会发生什么？

为什么这是一个问题？ : 有没有底层模型？底层模型如何工作？

<a id="d24e1964"></a>
不幸的是，简单的答案已经很少了。但是，凭借您广泛的作品集，并对您将阅读的大量技术文章进行一些批判性分析，您可以理解复杂的答案。
