## 主题 3. 软件熵

<a id="d24e1065"></a>
虽然软件开发不受几乎所有物理定律的影响，但熵的不可避免的增加给我们带来了沉重打击。熵是物理学中的一个术语，指的是系统中“无序”的数量。不幸的是，热力学定律保证宇宙中的熵趋向于最大值。当软件中的无序增加时，我们称之为“软件腐烂”。有些人可能会用更乐观的术语称之为“技术债务”，暗示他们有一天会偿还债务。他们可能不会。

<a id="d24e1082"></a>
但无论名称如何，债务和腐烂都可能无法控制地蔓延。

<a id="d24e1084"></a>
有很多因素会导致软件失效。最重要的似乎是项目中起作用的心理或文化。即使你是一个团队，你的项目的心理也可能是一件非常微妙的事情。尽管有最周密的计划和最优秀的人员，一个项目在其生命周期中仍然可能会经历毁灭和衰退。然而，还有其他一些项目，尽管面临巨大的困难和不断的挫折，仍然成功地对抗了自然的无序倾向，并取得了不错的结果。

<a id="d24e1086"></a>
有何不同？

<a id="d24e1088"></a>
<a id="FNPTR-5"></a>
在市中心，有些建筑美丽干净，而另一些则已是腐烂的废墟。为什么？犯罪和城市衰败领域的研究人员发现了一种令人着迷的触发机制，该机制可以很快将一栋干净、完整、有人居住的建筑变成一座被毁坏和废弃的废弃建筑。[[5]](<07 Communicate - communicate.md#FOOTNOTE-5>)

<a id="d24e1094"></a>
一扇破碎的窗户。

<a id="d24e1096"></a>
一扇破损的窗户在很长一段时间内没有得到修复，会给大楼里的居民带来一种被遗弃的感觉——一种权力不关心这座大楼的感觉。所以另一扇窗户被打破了。人们开始乱扔垃圾。出现涂鸦。严重的结构性损坏开始出现。在相对较短的时间内，建筑物的损坏超出了业主的修复意愿，被遗弃的感觉变成了现实。

<a id="d24e1098"></a>
<a id="FNPTR-6"></a>
为什么这会有所不同？心理学家所做的研究[[6]](<07 Communicate - communicate.md#FOOTNOTE-6>) 表明绝望可以传染。近距离思考流感病毒。忽视明显破裂的情况会强化这样的想法：也许没有什么可以解决，没有人关心，一切都注定了；所有消极的想法都会在团队成员中传播，形成恶性循环。

**提示 5：不要忍受破损的窗户**

<a id="d24e1119"></a>
不要让“破损的窗户”（糟糕的设计、错误的决定或糟糕的代码）得不到修复。一旦发现就立即修复。如果没有足够的时间来正确修复它，那就用木板把它封起来。也许你可以注释掉有问题的代码，或者显示“未实现”消息，或者替换虚拟数据。采取一些行动来防止进一步的损害，并表明你已经掌握了情况。

<a id="d24e1127"></a>
我们已经看到，一旦窗户开始破损，干净、功能齐全的系统就会很快恶化。还有其他因素可能会导致软件腐烂，我们将在其他地方讨论其中一些因素，但忽视比任何其他因素都更快地加速腐烂。

<a id="d24e1132"></a>
您可能会认为没有人有时间四处清理项目中的所有碎玻璃。如果是这样，那么你最好计划买一个垃圾箱，或者搬到另一个社区。不要让熵获胜。

### 首先，不造成伤害

<a id="d24e1137"></a>
安迪曾经有一个熟人，他非常富有。他的房子一尘不染，里面摆满了无价的古董、艺术品等等。有一天，一张挂毯离壁炉太近了，着火了。消防队赶来拯救了这一天，也拯救了他的房子。但在他们把又大又脏的水管拖进屋里之前，他们在火势熊熊的情况下停下来，在前门和火源之间铺了一块垫子。

<a id="d24e1149"></a>
他们不想弄乱地毯。

<a id="d24e1151"></a>
现在这听起来相当极端。当然，消防部门的首要任务是扑灭火灾，不管附带损害如何。但他们显然已经评估了情况，对自己控制火灾的能力充满信心，并小心翼翼地避免对财产造成不必要的损害。软件必须如此：不要仅仅因为存在某种危机就造成附带损害。一扇破碎的窗户就太多了。

<a id="d24e1153"></a>
一个破损的窗口——一段设计糟糕的代码，一个团队在项目期间必须忍受的糟糕的管理决策——就是开始衰退的唯一原因。如果您发现自己正在处理一个有很多破损窗口的项目，那么很容易陷入“所有其余代码都是垃圾，我就效仿”的心态。到目前为止，项目是否顺利并不重要。在导致“破窗理论”的最初实验中，一辆废弃的汽车原封不动地放置了一个星期。但一旦其中一扇窗户被打破，汽车就会在数小时内被剥光并翻个底朝天。

<a id="d24e1158"></a>
出于同样的原因，如果您发现自己所在的项目的代码非常漂亮——编写干净、设计良好且优雅——您可能会特别小心，不要把它搞砸，就像消防员一样。即使有大火（截止日期、发布日期、贸易展览演示等），您也不想成为第一个制造混乱并造成额外损害的人。

<a id="d24e1163"></a>
只要告诉自己，“窗户不要被打破。”

### 挑战

<a id="d24e1183"></a>
<a id="d24e1205"></a>
- 通过调查您的项目社区来帮助加强您的团队。选择两到三个破损的窗户，与同事讨论问题所在以及可以采取哪些措施来解决这些问题。
- 你能分辨出窗户什么时候第一次被打破吗？你的反应是什么？如果这是其他人的决定或管理层法令的结果，你能做什么？
