# 第 2 章 - 务实的方法

<a id="d24e2550"></a>
有一些适用于软件开发各个级别的提示和技巧、几乎通用的流程以及几乎是公理化的想法。然而，这些方法很少被记录下来；你通常会发现它们在设计、项目管理或编码的讨论中被写成奇怪的句子。但为了您的方便，我们将在这里将这些想法和流程整合在一起。

<a id="d24e2552"></a>
第一个也许是最重要的主题涉及软件开发的核心：主题 8，[*优秀设计的本质*](<08 The Essence of Good Design - essence_of_design.md#essence_of_design>)。一切都由此而来。

<a id="d24e2568"></a>
接下来的两个部分，主题 9，[*DRY——重复的弊端*](<09 DRY - The Evils of Duplication - dry.md#dry>) 和主题 10，[*正交性*](<10 Orthogonality - orthogonality.md#orthogonality>)，密切相关。第一个警告您不要在整个系统中重复知识，第二个警告您不要将任何一个知识分散到多个系统组件中。

<a id="d24e2586"></a>
随着变革步伐的加快，保持我们的应用程序的相关性变得越来越困难。在主题 11 [*可逆性*](<11 Reversibility - reversi.md#reversi>) 中，我们将介绍一些有助于使您的项目免受不断变化的环境影响的技术。

<a id="d24e2602"></a>
接下来的两节也相关。在主题 12 [*曳光弹*](<12 Tracer Bullets - tracer_bullets.md#tracer_bullets>) 中，我们讨论了一种允许您同时收集需求、测试设计和实现代码的开发风格。这是跟上现代生活节奏的唯一途径。

<a id="d24e2620"></a>
主题 13，[*原型和便利贴*](<13 Prototypes and Post-it Notes - prototyping.md#prototyping>) 向您展示如何使用原型来测试架构、算法、接口和想法。在现代世界，在全心投入想法之前测试想法并获取反馈至关重要。

<a id="d24e2631"></a>
随着计算机科学的慢慢成熟，设计者正在创造越来越高级的语言。虽然接受“make it so”的编译器尚未发明，但在主题 14 [*领域语言*](<14 Domain Languages - domain_languages.md#domain_languages>) 中，我们提出了一些更温和的建议，您可以自己实现。

<a id="d24e2649"></a>
最后，我们都在一个时间和资源有限的世界中工作。如果您善于计算出事情需要多长时间，您就可以更好地度过这些稀缺问题（并让您的老板或客户更高兴），我们将在主题 15，[*估计*](<15 Estimating - learn_to_estimate.md#learn_to_estimate>) 中对此进行介绍。

<a id="d24e2663"></a>
在开发过程中牢记这些基本原则，您将编写出更好、更快、更强的代码。您甚至可以让它看起来很简单。
