## 主题 12. 曳光弹

> 准备，开火，瞄准……
>
> 匿名

<a id="d24e5024"></a>
当我们开发软件时，我们经常谈论达到目标。我们实际上并没有在射击场发射任何东西，但这仍然是一个有用且非常直观的隐喻。特别是，考虑如何在复杂多变的世界中击中目标是很有趣的。

<a id="d24e5043"></a>
当然，答案取决于您所针对的设备的性质。对于许多人来说，你只有一次瞄准的机会，然后看看你是否击中靶心。但还有更好的方法。

<a id="d24e5045"></a>
你知道那些人们用机关枪射击的电影、电视节目和电子游戏吗？在这些场景中，您经常会看到子弹的路径是空气中的明亮条纹。这些条纹来自曳光弹。

<a id="d24e5047"></a>
曳光弹与常规弹药间隔一段时间装填。当它们被发射时，它们的磷会点燃，并在枪口和被击中的物体上留下烟火痕迹。如果曳光弹击中目标，那么普通子弹也击中目标。士兵们使用这些曳光弹来完善他们的目标：这是实际情况下的务实、实时反馈。

<a id="d24e5053"></a>
同样的原则也适用于项目，特别是当您正在构建以前从未构建过的东西时。我们使用“曳光弹开发”这个术语来形象地说明在实际情况下目标不断变化时需要立即反馈的必要性。

<a id="d24e5058"></a>
就像枪手一样，你试图在黑暗中击中目标。因为您的用户以前从未见过这样的系统，所以他们的要求可能很模糊。由于您可能使用不熟悉的算法、技术、语言或库，因此您面临大量未知因素。由于项目需要时间才能完成，因此您几乎可以保证在完成之前您所工作的环境将会发生变化。

<a id="d24e5060"></a>
典型的反应就是将系统指定为死亡。制作大量纸张，逐项列出每项要求，限制每项未知因素，并限制环境。使用航位推测法开枪。预先进行一项重大计算，然后射击并希望。

<a id="d24e5062"></a>
然而，务实的程序员往往更喜欢使用相当于曳光弹的软件。

### 在黑暗中发光的代码

<a id="d24e5067"></a>
曳光弹之所以有效，是因为它们与真正的子弹在相同的环境和相同的约束下运行。他们快速到达目标，因此炮手可以立即得到反馈。从实用的角度来看，它们是一个相对便宜的解决方案。

<a id="d24e5073"></a>
为了在代码中获得相同的效果，我们寻找能够快速、明显且可重复地从需求到最终系统的某些方面的东西。

<a id="d24e5075"></a>
寻找重要的需求，即定义系统的需求。寻找您有疑虑的领域以及您认为风险最大的领域。然后优先考虑您的开发，以便这些是您首先编码的领域。

**提示 20：使用曳光弹寻找目标**

<a id="d24e5083"></a>
事实上，考虑到当今项目设置的复杂性以及大量外部依赖项和工具，示踪子弹变得更加重要。对于我们来说，第一个跟踪项目只是创建项目，添加“hello world！”，并确保它编译并运行。然后，我们在整个应用程序中寻找不确定的区域，并添加使其工作所需的框架。

<a id="d24e5088"></a>
看看下图。该系统有五个架构层。我们对它们如何集成有些担忧，因此我们寻找一个简单的功能来让我们一起练习它们。对角线显示了该功能在代码中所采用的路径。为了使其工作，我们只需要在每一层中实现纯阴影区域：带有波浪线的东西将在稍后完成。

图中显示了五个垂直条。每个栏中的一个部分都会突出显示。穿过每个条的突出显示区域的对角线。突出显示区域以外的区域表示“尚未实施”。条形分别代表用户界面、授权、业务逻辑、数据模型和数据库。

<a id="d24e5095"></a>
我们曾经承担过一个复杂的客户端-服务器数据库营销项目。其要求的一部分是能够指定和执行临时查询。服务器是一系列关系数据库和专用数据库。客户端 UI 以随机语言 A 编写，使用一组以不同语言编写的库来向服务器提供接口。用户的查询以类似 Lisp 的表示法存储在服务器上，然后在执行之前转换为优化的 SQL。有许多未知因素和许多不同的环境，没有人太确定 UI 应该如何表现。

<a id="d24e5097"></a>
这是使用跟踪代码的绝佳机会。我们开发了前端框架、用于表示查询的库以及用于将存储的查询转换为特定于数据库的查询的结构。然后我们把它们放在一起并检查它是否有效。对于初始构建，我们所能做的就是提交一个列出表中所有行的查询，但它证明了 UI 可以与库对话，库可以序列化和反序列化查询，并且服务器可以从结果生成 SQL。在接下来的几个月里，我们逐渐充实了这个基本结构，通过并行增强跟踪器代码的每个组件来添加新功能。当 UI 添加新的查询类型时，库就会增长，SQL 生成也会变得更加复杂。

<a id="d24e5099"></a>
跟踪器代码不是一次性的：您编写它是为了保留。它包含任何生产代码都具有的所有错误检查、结构化、文档和自检功能。它根本就没有完全发挥作用。但是，一旦您在系统组件之间实现了端到端连接，您就可以检查与目标的距离，并在必要时进行调整。一旦达到目标，添加功能就很容易了。

<a id="d24e5102"></a>
Tracer 开发与项目永远不会完成的理念是一致的：总是需要进行更改并添加功能。这是一种渐进的方法。

<a id="d24e5113"></a>
传统的替代方案是一种繁重的工程方法：将代码划分为模块，然后在真空中进行编码。模块被组合成子组件，然后进一步组合，直到有一天您拥有完整的应用程序。只有这样才能将应用程序作为一个整体呈现给用户并进行测试。

<a id="d24e5115"></a>
跟踪代码方法有很多优点：

<a id="d24e5121"></a>
<a id="d24e5142"></a>
<a id="d24e5151"></a>
<a id="d24e5165"></a>
<a id="d24e5172"></a>
用户可以尽早看到正在运行的东西：如果您成功地传达了您正在做的事情（请参阅主题 52，[*取悦您的用户*](<../09 Pragmatic Projects/52 Delight Your Users - delight.md#delight>)），您的用户就会知道他们看到的是不成熟的东西。他们不会因为缺乏功能而感到失望；他们会欣喜若狂地看到他们的系统取得了一些明显的进展。随着项目的进展，他们还可以做出贡献，增加他们的支持度。这些相同的用户很可能会告诉您每次迭代与目标的接近程度。

开发人员构建一个工作结构：最令人畏惧的一张纸是上面什么也没写的纸。如果您已经解决了应用程序的所有端到端交互，并将它们体现在代码中，那么您的团队将不需要凭空做那么多事情。这使每个人都更有生产力，并鼓励一致性。

您拥有一个集成平台：由于系统是端到端连接的，因此您拥有一个环境，您可以在经过单元测试后添加新的代码片段。您将每天进行集成（通常是一天多次），而不是尝试一次大爆炸式集成。每个新更改的影响更加明显，并且交互更加有限，因此调试和测试更快、更准确。

你有一些东西要展示：项目赞助商和高层往往希望在最不方便的时候看到演示。通过跟踪代码，您将始终可以向他们展示一些内容。

您对进展有更好的感觉：在跟踪器代码开发中，开发人员会一一处理用例。当一个完成后，他们就会转移到下一个。衡量性能并向用户展示进度要容易得多。由于每个单独的开发都较小，因此您可以避免创建那些每周报告完成率为 95% 的整体代码块。

### 曳光弹并不总能击中目标

<a id="d24e5184"></a>
曳光弹会显示你击中的物体。这可能并不总是目标。然后你调整你的目标，直到他们瞄准目标。这就是重点。

<a id="d24e5186"></a>
跟踪代码也是如此。在您不能 100% 确定自己要去哪里的情况下，您可以使用该技术。如果您的前几次尝试失败了，您不应该感到惊讶：用户说“这不是我的意思”，或者您需要的数据在您需要时不可用，或者可能出现性能问题。因此，更改您所必须的内容以使其更接近目标，并感谢您使用了精益开发方法；一小部分代码具有较低的惯性 - 更改起来很容易且快速。您将能够收集有关应用程序的反馈，并快速且廉价地生成新的、更准确的版本。而且由于每个主要应用程序组件都在跟踪器代码中表示，因此您的用户可以确信他们所看到的内容是基于现实的，而不仅仅是纸质规范。

### 跟踪代码与原型设计

<a id="d24e5195"></a>
您可能会认为这个跟踪器代码概念只不过是在一个激进的名称下进行原型设计。有一个区别。通过原型，您的目标是探索最终系统的特定方面。有了真正的原型，您将抛弃在尝试该概念时捆绑在一起的所有内容，并使用您学到的经验教训对其进行正确的重新编码。

<a id="d24e5201"></a>
例如，假设您正在开发一个应用程序，帮助托运人确定如何将奇数尺寸的盒子装入集装箱。除其他问题外，用户界面需要直观，并且用于确定最佳包装的算法非常复杂。

<a id="d24e5203"></a>
您可以在 UI 工具中为最终用户设计用户界面原型。您编写的代码仅足以使界面响应用户操作。一旦他们同意布局，您可能会扔掉它并重新编码，这次是使用目标语言背后的业务逻辑。同样，您可能想要原型化许多执行实际打包的算法。您可以使用高级、宽容的语言（例如 Python）编写功能测试代码，并使用更接近机器的语言编写低级性能测试代码。无论如何，一旦做出决定，您就需要重新开始并在最终环境中编写算法，与现实世界相连接。这就是原型设计，非常有用。

<a id="d24e5217"></a>
跟踪代码方法解决了一个不同的问题。您需要知道应用程序作为一个整体是如何组合在一起的。您希望向用户展示交互在实践中如何工作，并且希望为开发人员提供一个可以挂载代码的架构框架。在这种情况下，您可以构建一个跟踪器，其中包含容器打包算法的简单实现（可能类似于先来先服务）和简单但有效的用户界面。一旦将应用程序中的所有组件组合在一起，您就拥有了一个向用户和开发人员展示的框架。随着时间的推移，您可以向该框架添加新功能，完成存根例程。但框架保持不变，并且您知道系统将继续按照第一个跟踪器代码完成时的方式运行。

<a id="d24e5223"></a>
这种区别非常重要，值得重复。原型设计生成一次性代码。 Tracer 代码简洁但完整，并且构成最终系统骨架的一部分。将原型设计视为在发射一颗曳光弹之前进行的侦察和情报收集。
