## 主题 33. 打破时间耦合

<a id="d24e16957"></a>
您可能会问，“时间耦合到底是什么？”。是时候了。

<a id="d24e16962"></a>
时间是软件架构中经常被忽视的一个方面。唯一让我们全神贯注的时间是时间表上的时间，即距离我们发货还剩下的时间——但这不是我们在这里讨论的内容。相反，我们讨论的是时间作为软件本身设计元素的作用。时间有两个方面对我们很重要：并发性（同时发生的事情）和顺序（事物在时间上的相对位置）。

<a id="d24e16997"></a>
我们在编程时通常不会考虑到这些方面。当人们第一次坐下来设计架构或编写程序时，事情往往是线性的。这就是大多数人的想法——做这个，然后总是做那个。但这样思考会导致时间耦合：时间上的耦合。方法 A 必须始终在方法 B 之前调用；一次只能运行一份报告；您必须等待屏幕重绘才能收到按钮点击。 Tick 必须在 tock 之前发生。

<a id="d24e17014"></a>
这种做法不太灵活，也不太现实。

<a id="d24e17016"></a>
我们需要允许并发并考虑解耦任何时间或顺序依赖性。通过这样做，我们可以获得灵活性并减少许多开发领域中基于时间的依赖性：工作流分析、架构、设计和部署。结果将是系统更容易推理，可能响应更快、更可靠。

### 寻找并发

<a id="d24e17021"></a>
<a id="FNPTR-46"></a>
在许多项目中，我们需要对应用程序工作流程进行建模和分析，作为设计的一部分。我们想知道什么可以同时发生，什么必须按严格的顺序发生。一种方法是使用活动图等符号来捕获工作流程。<a href="36%20Blackboards%20-%20blackboards#FOOTNOTE-46">[46]</a>

**技巧 56：分析工作流程以提高并发性**

<a id="d24e17072"></a>
活动图由一组绘制为圆框的操作组成。离开某个操作的箭头会导致另一个操作（第一个操作完成后即可开始）或一条称为同步栏的粗线。一旦完成同步栏的所有操作，您就可以沿着离开同步栏的任何箭头继续操作。没有箭头引导的动作可以随时开始。

<a id="d24e17082"></a>
您可以使用活动图来识别可以并行执行但实际上并未并行执行的活动，从而最大限度地提高并行性。

<a id="d24e17096"></a>
例如，我们可能正在为机器人果汁朗姆酒制造商编写软件。我们被告知步骤是：

|  |  |
| --- | --- |
| 1. 打开搅拌机 2. 打开果汁朗姆酒混合物 3. 将混合物放入搅拌机 4. 量取 1/2 杯白朗姆酒 5. 倒入朗姆酒 6. 添加 2 杯冰 | 1. 关闭搅拌机 2. 液化 1 分钟 3. 打开搅拌机 4. 取出玻璃杯 5. 取出粉色雨伞 6. 上菜 |

<a id="d24e17156"></a>
然而，如果调酒师按顺序一一遵循这些步骤，他就会丢掉工作。尽管它们连续地描述了这些操作，但其中许多操作可以并行执行。我们将使用以下活动图来捕获和推理潜在的并发性。

<a id="d24e17158"></a>
<a id="apina-colada"></a>
![An activity diagram represents the task carried out in a robotic piña coloda maker.](https://panzhongxian.cn/images/the-pragmatic-programmer/pina-colada.png)

活动图说明了机器人菠菜制造商中任务的潜在并发性。有十二个任务。第一个任务（打开搅拌机）和第二个任务（打开混合）并行发生。同样，第一个任务（打开搅拌机）和第四个任务（测量朗姆酒）并行发生。第三个任务将混合物放入搅拌机中，第六个任务添加两杯冰，第五个任务倒入朗姆酒同时进行。第五个任务导致第七个任务，关闭搅拌机。第八个任务是混合，第九个任务是打开搅拌机。第十个任务得到眼镜，第十一个任务得到粉色雨伞，第九个任务打开搅拌机导致最后一个任务，服务。

<a id="d24e17160"></a>
看到依赖关系真正存在的位置可能会让人大开眼界。在这种情况下，顶级任务（1、2、4、10 和 11）可以同时预先发生。任务 3、5 和 6 可以稍后并行发生。如果您参加了冰镇果汁朗姆酒制作比赛，这些优化可能会发挥重要作用。

更快的格式化

这本书是用纯文本写成的。为了构建要打印的版本、电子书或其他任何内容，该文本将通过处理器管道输入。有些寻找特定的结构（参考书目引文、索引条目、提示的特殊标记等等）。其他处理器对整个文档进行操作。

管道中的许多处理器必须访问外部信息（读取文件、写入文件、通过外部程序进行管道传输）。所有这些相对较慢的速度工作使我们有机会利用并发性：事实上，管道中的每个步骤都是并发执行的，从上一步读取并写入下一个步骤。

此外，该过程的某些部分相对来说是处理器密集型的。其中之一是数学公式的转换。由于各种历史原因，每个方程的转换可能需要长达 500 毫秒的时间。为了加快速度，我们利用并行性。因为每个公式都独立于其他公式，所以我们在其自己的并行过程中转换每个公式，并在结果可用时将其收集回书中。

因此，本书在多核机器上的构建速度要快得多。

### 并发机会

<a id="d24e17211"></a>
活动图显示了并发的潜在领域，但没有说明这些领域是否值得利用。例如，在冰镇果汁朗姆酒示例中，调酒师需要五只手才能同时运行所有潜在的初始任务。

<a id="d24e17213"></a>
这就是设计部分的用武之地。当我们查看活动时，我们意识到第 8 项“液化”需要一分钟。在此期间，我们的调酒师可以拿到眼镜和雨伞（活动 10 和 11），并且可能还有时间为其他顾客服务。

<a id="d24e17215"></a>
这就是我们在设计并发时所寻求的。我们希望找到需要时间的活动，但在我们的代码中不需要时间。查询数据库、访问外部服务、等待用户输入：所有这些事情通常都会阻止我们的程序直到完成。这些都是比 CPU 更高效的机会，相当于摆弄拇指。

### 并行的机会

<a id="d24e17229"></a>
请记住区别：并发是一种软件机制，而并行性是一个硬件问题。如果我们有多个处理器，无论是本地还是远程，那么如果我们可以在它们之间分配工作，我们就可以减少总体时间。

<a id="d24e17240"></a>
以这种方式划分的理想情况是相对独立的工作，其中每个工作都可以继续进行，而无需等待其他工作的任何结果。一种常见的模式是把一大块工作分成独立的块，并行处理每个块，然后组合结果。

<a id="d24e17242"></a>
实践中一个有趣的例子是 Elixir 语言的编译器的工作方式。当它启动时，它将正在构建的项目拆分为模块，并并行编译每个模块。有时，一个模块依赖于另一个模块，在这种情况下，其编译会暂停，直到另一个模块的构建结果可用为止。当顶层模块完成时，意味着所有依赖项都已编译完毕。结果是利用所有可用内核的快速编译。
