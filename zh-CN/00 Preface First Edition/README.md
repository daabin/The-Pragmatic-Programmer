# 第一版序摘录

<a id="rule-care"></a>

<a id="d24e378"></a>
本书将帮助您成为一名更好的程序员。

<a id="d24e380"></a>
您可能是一名孤独的开发人员、大型项目团队的成员，或者是同时与许多客户合作的顾问。没关系;本书将帮助您个人做得更好。本书不是理论性的——我们专注于实践主题，利用您的经验做​​出更明智的决策。实用一词源自拉丁语 pragmaticus，意为“业务熟练”，而后者又源自希腊语 πραγματικός，意思是“适合使用”。

<a id="d24e388"></a>
这是一本关于做的书。

<a id="d24e390"></a>
编程是一门手艺。最简单的是，它可以归结为让计算机执行您希望它执行的操作（或您的用户希望它执行的操作）。作为一名程序员，你一半是倾听者，一半是顾问，一半是解释者，一半是独裁者。您尝试捕获难以捉摸的需求并找到表达它们的方法，以便仅仅一台机器就可以满足它们。您尝试记录您的工作，以便其他人能够理解它，并且您尝试设计您的工作，以便其他人可以在其基础上进行构建。更重要的是，你试图在项目时钟的无情滴答声中完成这一切。你每天都在创造小奇迹。

<a id="d24e406"></a>
这是一项困难的工作。

<a id="d24e408"></a>
有很多人向您提供帮助。工具供应商吹捧他们的产品所创造的奇迹。方法论专家承诺他们的技术可以保证结果。每个人都声称他们的编程语言是最好的，每个操作系统都是所有可以想象到的弊病的答案。

<a id="d24e410"></a>
当然，这些都不是真的。没有简单的答案。无论是工具、语言还是操作系统，都没有最好的解决方案。只有更适合特定情况的系统。

<a id="d24e415"></a>
这就是实用主义的用武之地。您不应该拘泥于任何特定的技术，而应该拥有足够广泛的背景和经验基础，以便您在特定情况下选择好的解决方案。您的背景源于对计算机科学基本原理的理解，您的经验来自广泛的实际项目。理论与实践相结合，使你变得坚强。

<a id="d24e417"></a>
您调整自己的方法以适应当前的情况和环境。您判断影响项目的所有因素的相对重要性，并利用您的经验制定适当的解决方案。随着工作的进展，你会不断地这样做。务实的程序员能够完成工作，并且做得很好。
